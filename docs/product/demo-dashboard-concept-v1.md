## 1. 대시보드 목적

### 이 화면이 왜 필요한가

ERPNext 기본 화면은 "데이터를 입력하는 사람"을 위한 화면입니다. 메뉴를 탐색하고, DocType을 찾고, 필터를 걸고, 목록에서 원하는 행을 클릭하는 구조입니다. ERP를 잘 아는 사람에게는 익숙하지만, 중소기업 대표에게는 벽이 높습니다.

**대표가 원하는 것은 "데이터 입력"이 아니라 "지금 뭘 해야 하는지"입니다.**

이 대시보드는 ERPNext 기본 화면을 그대로 보여주는 것이 아니라, 중소기업 대표가 매일 아침 확인해야 하는 정보를 AI가 정리해주는 화면입니다.

### 핵심 목표

- "데이터 입력용 ERP"가 아니라 "대표 의사결정용 AI ERP"처럼 보이게 한다
- 대표가 로그인하자마자 "오늘 뭘 해야 하는지"가 먼저 보이게 한다
- ERPNext 표준 모듈은 그대로 유지하면서, 대시보드만 AI 기반으로 교체한다
- 첫 데모에서 "이건 기존 ERP가 아니라 AI ERP구나"라고 느끼게 한다

## 2. 핵심 사용자

### 사용자별 필요 정보

| 사용자 | 주요 관심사 | 대시보드 접근 |
|--------|------------|--------------|
| **대표** | 오늘 뭘 확인해야 하는지, 미수금, 납기, 매출 | **메인 대시보드 (첫 화면)** |
| 영업 담당자 | 견적서, 주문서, 고객 현황 | 영업 대시보드 (보조) |
| 재고/배송 담당자 | 재고 수준, 출하 예정, 입고 예정 | 재고 대시보드 (보조) |
| 사무/회계 담당자 | 미수금, 입금, 회계사 자료 | 회계 대시보드 (보조) |

### 첫 데모의 중심 사용자

**대표**

첫 데모는 대표를 위한 화면을 먼저 만듭니다. 영업, 재고, 회계 담당자용 대시보드는 향후 확장 대상입니다.

## 4. 대시보드 섹션 정의

### A. CEO Daily Briefing Card

**섹션명**: 오늘의 AI 브리핑

**화면에 표시할 내용**:
- 오늘 날짜와 요일
- AI가 생성한 3~5줄 요약
- 금융 현황 (미수금, 입금)
- 운영 현황 (납기, 출하)
- 오늘 해야 할 핵심 행동

**사용하는 ERPNext 데이터**:
| DocType | 필드 |
|---------|------|
| Sales Invoice | outstanding_amount, due_date, status, customer |
| Sales Order | delivery_date, status, customer |
| Payment Entry | posting_date, paid_amount, party |

**AI가 생성하는 문장** (예시):
```
2026-05-18 (월요일)

오늘 확인할 사항:
- 미수금 연체 1건: 서울건설 45,000,000원 (28일 연체)
- 이번 주 납기 2건: 광주디자인, 인천제조
- 재고 부족 1건: Steel Beam 100mm (100m 남음, 기준 200m)
- 이번 주 입금: 38,800,000원 (2건)

추천 행동: 서울건설에 지급 독촉 연락 권장
```

**사용자가 할 수 있는 행동**:
- "자세히 보기" 클릭 → 각 항목 상세 페이지로 이동
- "독촉 메일 초안" 클릭 → AI가 메일 초안 생성
- 브리핑 새로고침

**AI가 하면 안 되는 행동**:
- 자동으로 메일 발송
- 미수금 금액 변경
- 연체 상태 자동 수정

---

### B. Natural-language ERP Query Panel

**섹션명**: AI에게 물어보기

**화면에 표시할 내용**:
- 질문 입력창 (자연어)
- "보내기" 버튼
- AI 응답 영역 (표 또는 텍스트)
- 최근 질문 이력 (3~5개)

**사용하는 ERPNext 데이터**:
- 모든 DocType (Customer, Supplier, Item, Quotation, Sales Order, Purchase Order, Sales Invoice, Payment Entry, Stock Entry, Delivery Note)

**AI가 생성하는 문장** (예시):
```
질문: "이번 달 미수금 큰 거래처 보여줘"

응답:
| 거래처 | 청구서 | 미수금 | 기한 | 경과일 |
|--------|--------|--------|------|--------|
| 서울건설 | SINV-2026-001 | 45,000,000원 | 04/20 | 28일 |
| 부산테크 | SINV-2026-002 | 25,000,000원 | 07/06 | - |

총 미수금: 70,000,000원
```

**사용자가 할 수 있는 행동**:
- 질문 입력 후 Enter 또는 "보내기" 클릭
- 응답에서 거래처/청구서 클릭 → 해당 페이지로 이동
- "초안 만들기" 클릭 → 후속 조치 초안 생성

**AI가 하면 안 되는 행동**:
- 조회 결과를 자동으로 ERP에 저장
- 사용자 권한 밖의 데이터 반환
- DELETE, UPDATE 등 데이터 수정 쿼리 실행

---

### C. Receivables Summary Card

**섹션명**: 미수금 현황

**화면에 표시할 내용**:
- 총 미수금 금액
- 연체 건수
- 가장 큰 미수금 거래처 1~3건
- "상세 보기" 버튼

**사용하는 ERPNext 데이터**:
| DocType | 필드 |
|---------|------|
| Sales Invoice | outstanding_amount, due_date, status, customer |
| Customer | customer_name, payment_terms |

**AI가 생성하는 문장** (예시):
```
총 미수금: 70,000,000원
연체: 1건 (서울건설 45,000,000원, 28일)
정상: 1건 (부산테크 25,000,000원, 아직 기한 전)
```

**사용자가 할 수 있는 행동**:
- "상세 보기" → 미수금 전체 목록
- 거래처 클릭 → 고객 상세 페이지
- "독촉 초안" → AI가 독촉 메일 초안 생성

**AI가 하면 안 되는 행동**:
- 미수금 금액 변경
- 자동으로 독촉 메일 발송
- 대출 한도 변경

---

### D. Quotation Draft Assistant Card

**섹션명**: 견적서 빠른 작성

**화면에 표시할 내용**:
- 입력창: "어떤 견적을 만들까요?"
- "초안 생성" 버튼
- AI가 생성한 견적서 미리보기
- "ERPNext에 저장" 버튼 (사람이 클릭해야 저장됨)

**사용하는 ERPNext 데이터**:
| DocType | 필드 |
|---------|------|
| Customer | customer_name, payment_terms |
| Item | item_code, item_name, standard_rate, stock_uom |
| Price List | price_list_name, item_price |

**AI가 생성하는 문장** (예시):
```
입력: "서울건설에 Steel Beam 500미터 견적"

생성된 초안:
┌─────────────────────────────────┐
│ 견적서 초안                      │
│ 고객: 서울건설                    │
│ 품목: Steel Beam 100mm           │
│ 수량: 500m × 150,000원           │
│ 합계: 75,000,000원               │
│ 조건: Net 30                     │
│                                  │
│ [수정] [ERPNext에 저장] [취소]    │
└─────────────────────────────────┘
```

**사용자가 할 수 있는 행동**:
- 자연어로 견적 내용 입력
- "초안 생성" 클릭
- 초안에서 수량/단가 수정
- "ERPNext에 저장" 클릭 → Quotation DocType으로 저장

**AI가 하면 안 되는 행동**:
- 저장 버튼 없이 자동으로 견적서 저장
- 가격표 규칙 무시하고 할인 적용
- 비활성 고객에게 견적 생성
- 견적서를 고객에게 자동 발송

---

### E. Delivery and Stock Summary Card

**섹션명**: 배송 및 재고 현황

**화면에 표시할 내용**:
- 오늘/이번 주 출하 예정 건수
- 재고 부족 품목 (기준 수량 미달)
- 창고별 재고 요약
- "상세 보기" 버튼

**사용하는 ERPNext 데이터**:
| DocType | 필드 |
|---------|------|
| Sales Order | delivery_date, status, customer, item_code, qty |
| Delivery Note | posting_date, status, customer |
| Stock Entry | item_code, qty, source_warehouse, target_warehouse |
| Item | item_name, item_group |
| Bin | item_code, warehouse, actual_qty |

**AI가 생성하는 문장** (예시):
```
이번 주 출하 예정: 2건
- SO-2026-005: 광주디자인 (05/28 납기)
- SO-2026-003: 인천제조 (06/05 납기)

재고 부족: 1건
- Steel Beam 100mm: 100m (기준: 200m 이하 시 알림)

추천 행동: Steel Beam 구매 발주 검토
```

**사용자가 할 수 있는 행동**:
- "상세 보기" → 배송/재고 전체 목록
- "구매 발주 초안" → AI가 PO 초안 생성
- 품목 클릭 → 재고 상세 페이지

**AI가 하면 안 되는 행동**:
- 자동으로 구매 발주 생성
- 재고 수량 변경
- 창고 간 자동 이전

---

### F. Accountant Package Status Card

**섹션명**: 회계사 자료 준비 상태

**화면에 표시할 내용**:
- 현재 월 기준 자료 준비 상태
- 미완료 건수 (청구서, 영수증, 지급 건 등)
- "자료 확인하기" 버튼
- 마지막 내보내기 날짜

**사용하는 ERPNext 데이터**:
| DocType | 필드 |
|---------|------|
| Sales Invoice | posting_date, customer, grand_total, status |
| Purchase Invoice | posting_date, supplier, grand_total, status |
| Payment Entry | posting_date, paid_amount, party |
| Stock Entry | posting_date, item_code, qty, stock_entry_type |

**AI가 생성하는 문장** (예시):
```
5월 회계사 자료 준비 상태:
- 판매 청구서: 3건 발행, 2건 미수금
- 구매 발주: 3건
- 입금: 2건 (38,800,000원)
- 재고 이동: 5건

자료 준비: 80% 완료
미완료: 판매 청구서 1건 미수금 처리 필요
```

**사용자가 할 수 있는 행동**:
- "자료 확인하기" → 회계사 패키지 상세 페이지
- "내보내기" → CSV/PDF 다운로드
- "이메일 초안" → 회계사에게 보낼 이메일 초안 생성

**AI가 하면 안 되는 행동**:
- 회계사에게 자동으로 이메일 발송
- 전표(장부) 자동 생성
- 세금 신고 데이터 자동 제출

---

### G. Today's Action Items

**섹션명**: 오늘 할 일

**화면에 표시할 내용**:
- AI가 추천하는 오늘의 행동 목록
- 이 목록은 AI가 독립적으로 업무 결정을 내리는 것이 아니라, ERP 상태와 사전에 정한 규칙을 바탕으로 정리한 오늘의 확인 항목이다
- 우선순위 표시 (높음/보통/낮음)
- 각 항목 클릭 시 해당 페이지로 이동

**사용하는 ERPNext 데이터**:
- 모든 DocType의 상태, 기한, 금액 기반

**AI가 생성하는 문장** (예시):
```
오늘 할 일 (3건):

[높음] 서울건설 미수금 독촉 (SINV-2026-001, 45,000,000원, 28일 연체)
[보통] Steel Beam 재고 부족 → 구매 발주 검토
[보통] 광주디자인 납기 확인 (SO-2026-005, 05/28)
```

**사용자가 할 수 있는 행동**:
- 항목 클릭 → 해당 페이지로 이동
- "모두 확인함" 클릭 → 오늘 보기에서 숨김 (ERP 데이터 상태는 변경하지 않음)
- 개별 항목 "확인함" 처리

**AI가 하면 안 되는 행동**:
- 할 일을 자동으로 완료 처리
- ERP 데이터 상태를 자동으로 변경

## 6. ERPNext 기본 화면과의 관계

### 구현 원칙

**ERPNext core를 바로 수정하지 않는다.**

| 원칙 | 설명 |
|------|------|
| Core 미수정 | ERPNext 표준 코드를 직접 수정하지 않음 |
| Custom App | Padiem AI Module은 Frappe Custom App으로 구현 |
| 데이터 읽기 | ERPNext 데이터를 읽어서 AI 대시보드에 표시 |
| 표준 모듈 유지 | Selling, Buying, Stock 등 표준 모듈은 그대로 사용 |

### 첫 데모 구현 방식

첫 데모에서는 다음 중 하나의 방식으로 구현 가능:

| 방식 | 설명 | 장점 | 단점 |
|------|------|------|------|
| **Custom Page** | Frappe Custom Page로 대시보드 페이지 생성 | 완전한 자유도 | 개발 필요 |
| **Desk Workspace** | ERPNext Desk Workspace에 위젯 추가 | ERPNext 통합 | 자유도 제한 |
| **Report + AI Summary** | 기존 Report에 AI 요약 위젯 추가 | 빠른 구현 | 레이아웃 제한 |

**권장 방식**: Custom Page (가장 자유도 높음)

## 7. 첫 데모 시나리오

### 시나리오: 대표의 하루

**배경**: 도소매 기업 대표가 아침에 Padiem AI ERP에 로그인

**흐름**:

```
1. 로그인
   └→ CEO Dashboard 표시

2. CEO Daily Briefing 확인
   └→ "미수금 연체 1건: 서울건설 45,000,000원"
   └→ "이번 주 납기 2건: 광주디자인, 인천제조"
   └→ "재고 부족: Steel Beam 100mm"

3. Today's Action Items 확인
   └→ [높음] 서울건설 미수금 독촉
   └→ [보통] Steel Beam 구매 발주 검토
   └→ [보통] 광주디자인 납기 확인

4. AI Query Panel에 질문
   └→ 입력: "이번 달 미수금 큰 거래처 보여줘"
   └→ 응답: 표 형태로 미수금 목록 표시

5. Quotation Draft Assistant 사용
   └→ 입력: "서울건설에 Steel Beam 500미터 견적서 만들어줘"
   └→ 응답: 견적서 초안 생성
   └→ 대표가 확인 후 "ERPNext에 저장" 클릭

6. 회계사 자료 상태 확인
   └→ Accountant Package Status Card
   └→ "5월 자료 준비: 80% 완료"
```

### 데모 성공 기준

| 기준 | 확인 방법 |
|------|-----------|
| 대표가 "오늘 뭘 해야 하는지" 1분 안에 파악 | 브리핑 + Action Items 확인 |
| AI 질문에 정확한 데이터 반환 | Query Panel 테스트 |
| 견적서 초안을 2분 안에 생성 | Draft Assistant 테스트 |
| 기존 ERP와 다른 "AI ERP" 느낌 | 대표 피드백 수집 |

## 9. 구현 전제

### v1 제약 사항

| 제약 | 설명 |
|------|------|
| **Read-only 중심** | 대시보드는 데이터를 보여주고, AI는 요약/조회/초안까지만 |
| **저장은 사람이** | 견적서 초안 → 대표가 확인 → "저장" 클릭 → ERPNext에 저장 |
| **발송은 사람이** | 독촉 메일 초안 → 대표가 확인 → "발송" 클릭 |
| **승인은 사람이** | 모든 AI 출력물은 사람 승인 후 실행 |
| **회계/세무/급여 제외** | v1에서는 포함하지 않음 |

### AI 기능 범위 (v1)

| 기능 | v1 포함 | 설명 |
|------|---------|------|
| CEO 브리핑 | 예 | AI가 ERP 데이터 읽고 요약 |
| 자연어 조회 | 예 | 한국어로 ERP 데이터 검색 |
| 견적서 초안 | 예 | AI가 견적서 초안 생성 |
| 미수금 요약 | 예 | AI가 미수금 현황 요약 |
| 배송/재고 요약 | 예 | AI가 배송/재고 상태 요약 |
| 회계사 자료 요약 | 예 | AI가 월말 자료 준비 상태 요약 |
| 자동 저장 | 아니오 | 사람이 "저장" 클릭해야 저장 |
| 자동 발송 | 아니오 | 사람이 "발송" 클릭해야 발송 |
| 회계 처리 | 아니오 | 포함하지 않음 |
| 급여 처리 | 아니오 | 포함하지 않음 |
